# codmin Accessibility Audit

Status: local axe-core audit harness run and documented for the base
admin surface; the AKP-0007 Circle admin work extends the audit surface
to the new `/circles/*` routes.

## AKP-0007 Circle admin

- New `/circles`, `/circles/new`, `/circles/:id`, `/circles/:id/members`,
  `/circles/:id/scope` routes need to be added to the
  `tests/e2e/a11y.spec.ts` `authenticatedRoutes` list. Gated on
  seeded fixtures: runs the next time the example stack exports
  `CODMIN_E2E_ADMIN_EMAIL` / `CODMIN_E2E_ADMIN_PASSWORD` plus a
  Realm with at least one Circle.
- All form inputs added for Circle admin use the shared `Input` / `Label`
  pairing with explicit `id` / `for` attributes so the existing axe
  rules cover them.
- `RealmClassificationBadge` is a non-interactive Badge with text
  content; no aria-label required.
- ConfirmDialog gates (archive / tombstone) reuse the existing
  pattern that already passes the axe baseline.

## Automated coverage

- Main authenticated app shell now exposes a `main` landmark through `src/components/layout.rs`.
- Shared `Input` supports stable `id`, `name`, and `aria-label`; `SearchInput` now renders a screen-reader-only wrapped label.
- Axe-core Playwright coverage lives in `tests/e2e/a11y.spec.ts` and
  is invoked via `npm run test:a11y`. The suite has two modes:
  - with `CODMIN_E2E_ADMIN_EMAIL` / `CODMIN_E2E_ADMIN_PASSWORD`, it
    scans the authenticated routes `/`, `/devices`, `/federation`,
    `/audit`, `/policy`, `/server-status`. This is the release-gate
    path and supersedes the former "run axe against authenticated
    routes once credentials are seeded" manual verification step;
  - without credentials, it still scans the deployed public `/login`
    route instead of skipping the whole audit.
- Lighthouse accessibility category enforced at `>= 0.9` via
  `lighthouserc.json` (`npm run lhci`).
- Phase 5 — dark-mode `--muted-foreground` was lifted from 60% to 78%
  lightness so axe's `color-contrast` rule (which used to be disabled
  in `tests/e2e/a11y.spec.ts`) is now re-enabled. The pair
  `hsl(270 8% 78%)` on `hsl(270 22% 10%)` measures ~7.5:1, well above
  the 4.5 WCAG AA threshold for body text. Re-run `npm run lhci` to
  confirm the Lighthouse a11y score remains ≥ 0.9 after the token
  change.
- Keyboard-only smoke coverage for devices, peers/federation, audit,
  and policy lives in `tests/e2e/keyboard-strands.spec.ts`
  (`npm run test:keyboard`).
- Form controls reviewed in the Phase 3 touched pages: realm-destroy, realm-links, and server-status retain visible labels, accessible names, or structured landmarks.
