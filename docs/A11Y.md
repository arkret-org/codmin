# Accessibility verification

Build with `python scripts/build-web.py --release`, then serve Cargo's reported
`target_directory/web` using `node scripts/serve-spa.mjs <directory> 4173`.
The application uses Glory semantic controls and Sapid widgets. The responsive
shell owns its navigation drawer and keyboard behavior; authentication pages
expose a main landmark. Destructive actions use inline confirmation phrases
and validated audit reasons, so no modal focus trap is needed for those forms.

Run `npm run test:a11y` against `CODMIN_E2E_BASE_URL`, or use the isolated migration
suite with `npm run test:migration`.
The latter uses mocked HTTP contracts to drive the real compiled WASM app;
it does not prove backend authorization or real OAuth provider integration.

Check desktop and mobile navigation, keyboard focus, loading/error/retry,
confirmed sign-out, labels, and dangerous action gating. Existing live-service
suites require seeded services and operator credentials. New framework builds
do not inherit the previous framework's accessibility acceptance results.
OS screen readers and IME require separate manual acceptance.
