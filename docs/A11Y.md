# codmin a11y — CI + manual procedure

The root [`A11Y.md`](../A11Y.md) documents codmin's accessibility claims
(WCAG 2.1 AA target, keyboard navigation matrix, contrast checks). This
document covers the **verification procedure**: how to run axe-core
against a built codmin SPA either locally or as part of CI.

## CI

The repo carries an `.github/workflows/a11y.yml` job that:

1. Builds the Dioxus SPA in release mode (`dx build --release`).
2. Serves the bundle on `http://127.0.0.1:4173`.
3. Walks a representative set of admin pages with Playwright +
   `@axe-core/playwright` and fails on any `serious` or `critical`
   violation.

The main `.github/workflows/check.yml` pipeline also gates the built
artifact with Playwright smoke, axe, keyboard-only, RTL-overflow, and
Lighthouse budget checks. Authenticated Playwright cases still require
`CODMIN_E2E_ADMIN_EMAIL` / `CODMIN_E2E_ADMIN_PASSWORD`; public checks run
against the static SPA served from the CI artifact.

The harness script (`scripts/a11y/axe-scan.mjs`) is a thin wrapper around
`@axe-core/playwright`. The page list is currently:

| Path | Notes |
| --- | --- |
| `/` | Login + dashboard shell. |
| `/agents` | Cursor-paginated list view; checks live region announcements. |
| `/agents/admin` | Admin registration view; checks label association and error banner ARIA. |
| `/agents/personal` | Personal-agent list and provision strand entry point. |
| `/circles` | List + detail; verifies `DangerousActionDialog` focus trap. |

Add a path to the page list when a new admin section ships.

## Manual procedure

When CI is unavailable (e.g. operator on an air-gapped network):

1. `dx serve --release` — builds and serves the SPA locally on
   `http://127.0.0.1:8080`.
2. In Chrome, open DevTools → "Lighthouse" → run the Accessibility
   audit. Score < 95 fails.
3. Optionally install the `axe DevTools` Chrome extension and run a
   manual scan against each path in the table above. Promote any
   `serious` / `critical` finding to a `_codmin_todos.md` entry.

## Known limitations

* The Dioxus SPA renders most content client-side, so axe must wait for
  the WASM bundle to hydrate before scanning. The CI harness waits on
  the `[data-loaded="true"]` attribute that `App` sets after the initial
  render.
* The `DangerousActionDialog` focus trap relies on `inert` polyfilling
  in browsers older than Chrome 102 / Firefox 112 — bundle that
  polyfill if you support older operator environments.
